## Review result

- Tab split already existed. The review fixed double-click rename when the target tab was inactive and kept the active pane's input separate across splits.
- Ctrl+A/Ctrl+X selection editing works in Fish. Fish undo and redo history now resets on each executed command.
- Alternate-screen applications receive their raw Ctrl+A, Ctrl+X, Ctrl+V, Ctrl+Z, function, and navigation key sequences. Ctrl+Shift clipboard shortcuts remain available; Ctrl+Shift+F1 opens About.
- The header reflects the foreground PTY process's local root and SSH context. It shows `?` if the process namespace cannot reveal the context; SSH cannot prove the remote account's privilege level.
- Shell input boundaries use OSC 133 cell semantics when present, avoiding prompt-text heuristics for commands such as `echo > file`.
- GUI tests use a private display and shims for `toolbox`, `podman`, and `flatpak-spawn`. Container-launch behavior is covered with test doubles. A real shared developer container was deliberately excluded from the review run.

## Performance snapshot

These are local measurements from the reviewed commit, not guaranteed refresh rates. Criterion measured the Ghostty parser, snapshot, and app-frame CPU path; the held-key test measured a real GTK window under Xvfb with sustained keyboard input.

| Scenario | Result |
| --- | ---: |
| One dirty row in a 240×67 terminal | 51.5 µs median |
| Forced full snapshot of 240×67 cells | 1.63 ms median |
| 128 input frames through the full app-frame path | 3.03 ms total, about 23.7 µs per frame |
| GTK render / paint, held-key p95 | 0.694 / 1.10 ms |
| GTK input-to-render, held-key p95 | 12.1 ms |
| GTK frame interval, held-key p50 | 16.67 ms under Xvfb |
| Steady process RSS growth during held-key test | 6.6 MiB |

The held-key E2E performance gate passed. Its frame interval reflects Xvfb's presentation cadence; it does not establish a 120 or 240 Hz desktop refresh rate.
